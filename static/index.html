Keys

CipherDrop doesn't manage accounts or persistent keys — there's nothing to configure. Here's exactly what happens instead.

Encapsulation key (ek)
800 bytes · generated fresh for every file · discarded immediately after use, never transmitted anywhere
Decapsulation key (dk)
1632 bytes · lives only in the shared link's URL fragment (after the "#") · browsers never send this to any server
Session key
32 bytes · derived once via ML-KEM-512 encapsulation · used for that single file's AES-256-GCM encryption, then gone

Because there's no persistent identity behind any of this, it doesn't yet defend against an attacker who records network traffic today and gains a quantum computer years from now — that specific defense needs published, long-lived recipient keys, which is on the roadmap, not in this build.
